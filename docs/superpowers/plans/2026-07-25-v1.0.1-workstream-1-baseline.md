# Hermes Brain v1.0.1 Workstream 1 Implementation Plan

**Workstream:** Baseline and characterization  
**Design:** `docs/superpowers/specs/2026-07-25-v1.0.1-production-readiness-design.md`  
**Target platform:** Linux  
**Target Python:** 3.11, 3.12, and 3.13  
**Target Hermes releases:** 0.19.0 (`v2026.7.20`) and 0.18.2 (`v2026.7.7.2`)

## Goal

Create a reproducible baseline that protects existing behavior and turns every confirmed production blocker into an executable regression contract. This workstream does not repair the blockers; expected failures remain visible as strict `xfail` tests until their owning workstream fixes them.

## Safety rules

- Preserve all pre-existing modified and untracked files.
- Use targeted edits; do not reset, stash, or reformat unrelated user changes.
- Do not call live Notion or Sentry services.
- Do not publish, tag, commit, or push.
- Keep each regression test deterministic and self-cleaning.
- Mark known broken behavior with `pytest.mark.xfail(strict=True)` so an unexpected pass fails until the marker is deliberately removed.

## Task 3: Add stable public-behavior characterization tests

**Create:** `tests/characterization/__init__.py`  
**Create:** `tests/characterization/test_provider_contract.py`  
**Create:** `tests/characterization/test_cli_contract.py`

Add passing tests for behavior that must remain compatible during refactoring:

### Provider registration

- `register(ctx)` registers one `NotionBrainProvider`.
- Provider name remains `notion_brain`.
- `is_available()` checks configuration without making a Notion network call.
- Public tool calls return strings.
- Successful tool responses are JSON objects.
- Unknown tools return a safe error.

### Current lifecycle

- `initialize()` honors the provided `hermes_home` path.
- Initialization maps all cached database IDs.
- Initialization failure does not crash Hermes.
- `shutdown()` is safe before successful initialization.
- `system_prompt_block()` returns a stable provider description.

### Existing public helpers

- `normalize_domain()` and `database_for_domain()` retain accepted aliases.
- Property helper return shapes remain characterized until the Notion adapter replaces them.
- `python -m notion_brain --help` remains callable.
- Existing `health`, `url`, and `reset --dry-run` parser shapes remain characterized without network access.

Prefer assertions on behavior and structured outputs over implementation details.

## Task 4: Add strict regression contracts for storage and recall blockers

**Create:** `tests/regressions/__init__.py`  
**Create:** `tests/regressions/test_storage_recall_blockers.py`

Add strict expected-failure tests for:

1. **Full-body retrieval**
   - Mock a Notion search response followed by block-child responses.
   - Assert the returned entry contains the complete page body, not only the title or properties.

2. **Database-filtered search**
   - Return both matching and unrelated records from a database query.
   - Assert only records matching the supplied query appear.

3. **Pagination**
   - Mock two database pages using `has_more` and `next_cursor`.
   - Assert all records are returned and the second request carries `start_cursor`.

4. **Content preservation**
   - Pass content containing more than eight lines to the block formatter.
   - Assert no non-empty line is dropped.

5. **Domain/schema consistency**
   - Capture a write payload for each domain.
   - Assert every emitted select/status value is present in the corresponding bootstrap schema.

Every test includes the owning future workstream in its expected-failure reason.

**Validate:**

```bash
uv run --locked --extra dev pytest tests/regressions/test_storage_recall_blockers.py -q -rxX
```

Expected result: tests report strict expected failures and no unexpected passes.

## Task 5: Add strict regression contracts for durability and truthful status

**Create:** `tests/regressions/test_durability_blockers.py`

Add strict expected-failure tests for:

1. `remember` does not return `Saved` when no destination database exists.
2. A content update calls `update_page()` and does not create a duplicate page.
3. Starting two synchronizations does not allow concurrent write execution.
4. Session end and shutdown wait for every accepted synchronization operation.
5. A backend exception produces a failed response rather than a success response.
6. A retryable write remains represented after process shutdown instead of disappearing.

Use `threading.Event` barriers with bounded waits. Always release barriers in `finally` blocks so a failing test cannot leave worker threads hanging.

**Validate:**

```bash
uv run --locked --extra dev pytest tests/regressions/test_durability_blockers.py -q -rxX
```

Expected result: tests report strict expected failures and terminate deterministically.

## Task 6: Add strict regression contracts for migration and privacy blockers

**Create:** `tests/regressions/test_migration_privacy_blockers.py`

Add strict expected-failure tests for:

1. Startup does not archive or recreate a database because of a stale local schema version.
2. `health` remains read-only when a schema mismatch exists.
3. An incompatible migration preserves the original database until copied content is verified.
4. Task, content, research, session-summary, and mirror write paths all apply the same secret policy.
5. Common secret classes outside the current detector—AWS access keys, bearer tokens, credential-bearing URLs, and private-key headers—are blocked or redacted under the secure default.
6. User content and detected secret values do not appear in logs when a write fails.

Do not call the real filesystem outside pytest temporary directories and do not call Notion.

**Validate:**

```bash
uv run --locked --extra dev pytest tests/regressions/test_migration_privacy_blockers.py -q -rxX
```

Expected result: tests report strict expected failures and no secret samples are emitted by pytest logs.

## Workstream 1 definition of done

- Development and CI dependencies are exact and locked.
- The declared Python range matches supported Hermes releases.
- Existing stable behavior is protected by passing characterization tests.
- Every confirmed blocker in scope has a deterministic strict expected-failure regression.
- The baseline report records successes and failures accurately.
- CI runs tests before quality cleanup and exposes—not hides—the remaining debt.
- No live user data or credentials are used.
- No pre-existing user changes are overwritten.
- The roadmap records evidence and points to Workstream 2.
