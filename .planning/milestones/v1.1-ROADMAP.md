**Status:** ✅ SHIPPED 2026-10-07

## Overview

hermes-brain ships as a clean, modernly-packaged PyPI distribution with tokenless automated publishing, a CLI drift-detection command that prints copy-pasteable per-environment upgrade instructions, and a non-blocking background auto-update check with stale-while-revalidate caching. The release pipeline runs on `v*` tag pushes via OIDC trusted publishing; the runtime provider loads update status from a synchronous cache and refreshes it in the background on the existing sync worker — zero network on the startup path.

### Phase 5: CLI Update Drift Detection

**Goal**: Users running hermes-brain from any install mode (uv, pip venv, pip user, git clone) can check for newer releases and get exact, copy-pasteable upgrade instructions — without the tool ever modifying their environment.
**Depends on**: Nothing (independent of Phase 4; both can execute in any order)
**Requirements**: UPD-01, UPD-02, UPD-03, UPD-04, UPD-05
**Plans**: 1 plan

Plans:

- [x] 05-01: Add `notion_brain update` CLI subcommand detecting drift and printing per-mode upgrade command; expose `--check` and `--json`; remove any mutating behavior (UPD-01..05)

**Details:**
**Success Criteria** (what must be TRUE):

  1. `notion_brain update` prints the installed version and the latest GitHub release version, clearly showing drift when a newer release exists (UPD-01)
  2. The printed upgrade command is exact and copy-pasteable for the detected environment: `uv` / pip venv / pip user / git clone each get their correct command, using the `hermes-brain` PyPI distribution name for wheel/pip installs (UPD-02)
  3. Version comparison uses integer-tuple SemVer with pre-release ranking — `1.10.0` sorts above `1.9.0`, and `1.1.0` sorts above `1.1.0b1` (UPD-03)
  4. `notion_brain update --check` exits 0 when current and 2 when an update is available; `--json` emits a machine-readable payload parseable by scripts and CI (UPD-04)
  5. The command only detects and instructs — running it never executes `pip install`, `git pull`, or any other mutation of the running environment (UPD-05)

**Verification**: 5/5 must-haves verified, passed 2026-09-29 (re-verified after Phase 06 commit a0c7390 to refresh stale digest; no regressions).

### Phase 6: Cached Non-Blocking Auto-Update Check

**Goal**: The agent provider learns about new releases in the background with zero startup cost and zero network on the startup path.
**Depends on**: Phase 5 (reuses the update-check engine and cache format from the drift detection work)
**Requirements**: CHK-01, CHK-02, CHK-03, CHK-04, CHK-05
**Plans**: 1 plan

Plans:

- [x] 06-01: Add `$HERMES_HOME/.update_cache.json` with atomic writes + TTL; wire provider init to load cache synchronously and dispatch background refresh on expired TTL; refactor `health_report()` to read cache (CHK-01..05)

**Details:**
**Success Criteria** (what must be TRUE):

  1. Provider init reads `$HERMES_HOME/.update_cache.json` synchronously in under 1ms with zero network calls — verified with and without a network connection (CHK-01)
  2. When the cache TTL (default 24h, configurable) is expired, a refresh is dispatched to the existing `notion-brain-sync-worker` background queue and stale data is served until the refresh lands — no startup stall (CHK-02)
  3. Cache writes are atomic (tempfile + `os.replace`, mode `0o600`) and a corrupt or interrupted cache file degrades silently — startup never crashes with `JSONDecodeError` (CHK-03)
  4. `health_report()` shows cached update status instead of performing its own synchronous network update check (CHK-04)
  5. The background refresh queries the GitHub API unauthenticated with a ~2.5s timeout, redacts secrets from all error/log paths, and when offline no exception escapes to the worker (CHK-05)

**Verification**: 5/5 must-haves verified, passed 2026-10-07 (re-verified after commit a0c7390 to refresh stale digest; no regressions).

## Milestone Summary

**Decimal Phases:**

- (none) — no mid-milestone insertions.

**Key Decisions:**

- PEP 639 SPDX string `license = "MIT"` over legacy `{ text = ... }` table — modern packaging standard, no deprecation warnings on Python 3.11–3.13.
- OIDC trusted publishing over static PyPI API token — no long-lived credential in CI secrets, automatic expiry, passes modern security audits.
- Separate `build` and `publish` jobs in `publish.yml` with `id-token: write` scoped to `publish` only — least-privilege OIDC token exchange.
- Documented `docs/RELEASES.md` maintainer runbook with one-time Trusted Publisher setup, emergency twine fallback, and post-publish recovery — works without GitHub Actions.
- Detect + instruct, not auto-mutate, for `notion_brain update` — mutating the running virtualenv silently causes `ImportError`/corruption/PEP 668 races; users run the printed command themselves.
- Integer-tuple SemVer with pre-release ranking over string comparison — `1.10.0 > 1.9.0` and `1.1.0 > 1.1.0b1` come out right.
- GitHub API as remote source of truth over PyPI JSON — git-clone users get update notifications without PyPI lag, single source of truth.
- Stale-while-revalidate cache pattern for update check — synchronous cache read on startup (<1ms), background refresh on existing sync worker thread — zero network on the startup path.
- Dedicated `$HERMES_HOME/.update_cache.json` file over bundling in `notion_brain.json` — keeps package distribution state separate from Notion DB IDs; survives `reset --force`.
- Atomic write via tempfile + `os.replace` with `fsync` + mode `0o600` — survives crashes mid-write, no permission leak.
- Bare `except Exception` in `update_cache.refresh` with `redact_secrets` log — worker thread never crashes; secrets never reach logs.
- Wall-clock timeout check after the call (not inside the upstream) — preserves `_find_latest_tag` signature contract per plan prohibitions while bounding network exposure to ~2.5s.
