## v1.1 Requirements — All Complete

### PyPI Publishing (DIST)

- [x] **DIST-01** ✓: A `v*` tag push automatically builds wheel + sdist and uploads to PyPI via OIDC trusted publishing — no static PyPI API tokens in CI secrets. **Validated** (Phase 4, Plan 02).
- [x] **DIST-02** ✓: The publish workflow uses separate build and publish jobs, gated on `refs/tags/v*`, with `environment: pypi` and `id-token: write` so the OIDC token exchange succeeds. **Validated** (Phase 4, Plan 02).
- [x] **DIST-03** ✓: A documented manual twine runbook (build → `twine check` → `twine upload dist/*`) exists for offline/emergency releases when GitHub Actions or the OIDC exchange is unavailable. **Validated** (Phase 4, Plan 02).

### Build Metadata (META)

- [x] **META-01** ✓: `pyproject.toml` declares the PEP 639 SPDX string `license = "MIT"` and the deprecated `license = { text = "MIT" }` table is removed. **Validated** (Phase 4, Plan 01).
- [x] **META-02** ✓: Build-system floor is bumped to `setuptools>=77.0.3`; `python -m build` + `twine check` produce clean metadata with zero deprecation warnings on Python 3.11, 3.12, and 3.13. **Validated** (Phase 4, Plan 01).

### CLI Update Command (UPD)

- [x] **UPD-01** ✓: `notion_brain update` detects drift against the latest GitHub release and prints the installed version vs. the latest version. **Validated** (Phase 5, Plan 01).
- [x] **UPD-02** ✓: The command prints an exact, copy-pasteable upgrade command matching the detected environment (uv / pip venv / pip user / git clone). **Validated** (Phase 5, Plan 01).
- [x] **UPD-03** ✓: Version comparison uses integer-tuple SemVer with pre-release ranking — `1.10.0` sorts above `1.9.0` and `1.1.0` sorts above `1.1.0b1`. **Validated** (Phase 5, Plan 01).
- [x] **UPD-04** ✓: `--check` exits 0 when current and 2 when an update is available; `--json` emits a machine-readable payload. **Validated** (Phase 5, Plan 01).
- [x] **UPD-05** ✓: The command is detect + instruct only — it never mutates the running environment (no `pip install`, `git pull`, or virtualenv modification). **Validated** (Phase 5, Plan 01).

### Auto Update Check (CHK)

- [x] **CHK-01** ✓: Provider init reads `$HERMES_HOME/.update_cache.json` synchronously in <1ms with zero network calls on the startup path. **Validated** (Phase 6, Plan 01).
- [x] **CHK-02** ✓: When the cache TTL (default 24h, configurable) is expired, a refresh is dispatched to the existing `notion-brain-sync-worker` background queue and stale data is served until the refresh lands. **Validated** (Phase 6, Plan 01).
- [x] **CHK-03** ✓: Cache writes are atomic (tempfile + `os.replace`, mode `0o600`) with a `JSONDecodeError` guard so a corrupt or interrupted cache degrades silently and never crashes startup. **Validated** (Phase 6, Plan 01).
- [x] **CHK-04** ✓: `health_report()` no longer performs its own synchronous network update check and instead reads the cached update status. **Validated** (Phase 6, Plan 01).
- [x] **CHK-05** ✓: The refresh queries the GitHub API unauthenticated with a short timeout (~2.5s), redacts secrets from all error/log paths, and is offline-safe (no exception escapes when the network is down). **Validated** (Phase 6, Plan 01).
