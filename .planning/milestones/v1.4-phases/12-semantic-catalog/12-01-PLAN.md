# Phase 12 — CAT-01..03 Gap Closure Plan

## Gap assessment

No code gaps were found. The semantic catalog is implemented, provider-neutral, consumed by retrieval, and covered by existing tests:

- `notion_brain/catalog.py` defines `Term`, `Entity`, `Relation`, `StorageRef`, atomic redacted JSON persistence, and deterministic query APIs.
- `Catalog.resolve_term`, `list_entities`, and `get_relations` exist with the exact CAT-02 contract.
- `NotionAdapter.resolve_storage_ref` and `ObsidianVaultAdapter.resolve_storage_ref` map provider-neutral refs to concrete page/database ids and vault note paths.
- `NotionBrainProvider._tool_search` consumes `match_definitions`, resolves refs, and selects rows by page/database reference without requiring textual equality.
- `tests/test_catalog.py`, `tests/test_catalog_home.py`, `tests/test_catalog_search.py` and `tests/test_answerability.py` cover the models, queries, persistence scoping, provider consumption and reference-driven selection.

The milestone audit already marks CAT-01, CAT-02 and CAT-03 as **WIRED**. What is missing is original GSD closure evidence, not implementation.

## Addendum — 2026-11-12 gap review

A second-pass review found one real residual: the provider resolved Obsidian storage refs for the `definitions` payload but never used them to select vault rows, so a referenced note was still recalled only when its text matched the query. Closure added:

- `resolved_obsidian_paths` to the `_tool_search` catalog resolution, failure reset and row filter.
- `ObsidianVaultAdapter.get_note(path)` for targeted index lookup, because `search(query)` cannot surface a note whose text does not contain the query.
- Two regressions: `test_search_resolves_obsidian_note_ref_without_text_match` and `test_obsidian_get_note_returns_indexed_note_and_rejects_outside_paths`.

Final gate: **570 passed, 1 deselected**; ruff and mypy clean.
