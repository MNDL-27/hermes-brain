<objective>
Give hermes-brain a developer-facing pre-push hook (TOOL-01) that runs the same offline test gate CI uses, and a weekly scheduled `pre-commit autoupdate` workflow (TOOL-02) that keeps `.pre-commit-config.yaml` rev-pins current via an automated PR.

Purpose: TOOL-01 closes the "I have working code locally and CI just failed it" loop — a contributor runs the opt-in install once, then any local push that breaks the suite is blocked at `git push` time. TOOL-02 keeps the pre-commit hook rev-pins fresh without manual maintenance; a bot opens the PR, a maintainer squash-merges. Both artifacts land on top of Wave 1's hermetic suite (08-01), so the hook inherits `addopts = ["-m", "not network"]` and the autoupdate workflow can re-run `pre-commit` clean.

Output: `scripts/pre-push` (executable, ~50 lines of bash with the design from 08-RESEARCH.md §TOOL-01 Design lines 186–255); `.github/workflows/pre-commit-autoupdate.yml` (~50 lines of YAML mirroring `ci.yml` + `publish.yml` conventions with the workflow from 08-RESEARCH.md §TOOL-02 Design lines 257–349); CONTRIBUTING.md gains a "Local pre-push tests (opt-in)" subsection documenting the `cp` install command and `HERMES_BRAIN_SKIP_PRE_PUSH=1` escape hatch.
</objective>
