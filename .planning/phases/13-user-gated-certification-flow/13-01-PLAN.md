<task name="Isolate certification work after the accepted Truth flip" type="auto">
  <files>notion_brain/provider.py</files>
  <action>
    Restructure `_tool_certify` so the Truth write is isolated from optional follow-up work:

    - Perform `store.update_page(page_id, {"Truth": ...}, expected_database_id=db_id)` first. A failure here keeps the existing error return and must not reach predecessor processing.
    - After acceptance, wrap each optional concern separately, per peer:
      - the optional `Superseded Page ID` property update,
      - the catalog `supersedes` relation load/add/save,
      - the predecessor cache mirror.
    - Log each recoverable failure with `S.redact_secrets` and continue.
    - Do not let a catalog/metadata/cache failure escape the peer loop or change the successful `Certified: ...` return once Truth was accepted.
    - Keep the predecessor status flip itself meaningful: if the status update is rejected, skip that peer's metadata/graph/cache work and continue with the remaining peers.

    Reuse the failure-isolation shape already present in `_supersede_matching_active`; do not redesign certification permissions, Truth ranking or schema handling.
  </action>
  <verify>

    <fails_when>A catalog, metadata or cache failure after the Truth flip returns an error, suppresses the predecessor cache update, or stops later peers from being superseded.</fails_when>

  <done>An accepted certification returns success and completes every predecessor status flip plus cache mirroring, while auxiliary failures only appear as redacted warnings.</done>
