# Phase 19: Section-Aware References - Plan

## Goal
Enable catalog references to target specific markdown sections (`note.md#section`) within the Obsidian vault.

## Requirements
- REF-01: Support `note.md#section` syntax.
- Resolution: Path and section resolved independently.
- Retrieval: Replace row content with section text.
- Matching: Case-insensitive, slug-compatible.
- Concatenation: Multiple matching headings concatenated.
- Fallback: Full note + warning if section missing.

## Tasks
1. **Update Adapter API**:
   - Modify `ObsidianVaultAdapter.resolve_storage_ref` to handle `#section` fragments.
   - Add `resolve_storage_section` returning `(path, section_name)`.
   - *Verification*: Unit test `resolve_storage_ref` with `#section` and normal paths.
2. **Implement Section Resolution**:
   - Create logic to match headings (case-insensitive, slugs).
   - Handle duplicate headings by concatenating in order.
   - Implement nested section logic (include until next same-or-higher heading).
   - *Verification*: Mock markdown files with various heading patterns and verify `section_text` extraction.
3. **Integration into Provider**:
   - Update `notion_brain/provider.py` to use new resolution logic.
   - Update `_tool_search` post-filter to replace content with section text.
   - *Verification*: Integration test with real vault files or realistic mocks.
4. **Error Handling & Fallbacks**:
   - Log redacted warnings for missing sections.
   - Ensure fallback to full note content is seamless.
   - *Verification*: Test with non-existent sections.
